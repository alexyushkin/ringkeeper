## Earlier the same day

Three earlier full runs that day fell short, and each found something that was fixed before
this run:

- **27 of 31, on beta.35.**
  - **answer-by-name:** a reply of just "Demo site" also matched Demo shop's nickname "demo",
    so it wasn't taken as the answer. The self-test then sent the name again on every check,
    about 80 times in 8 minutes, and Ringkeeper started the same task 5 times.
  - **client-project-work:** a request naming only the client went to Demo shop without
    asking which project.
  - **pushed-by-record:** the model declined to touch Acme's data, but the check counted the
    task's ending "not done" as a failure.
  - **client-default:** the router told the worker not to open any email, and the demo
    inbox had no dates, so it couldn't tell which email was newest.
- **27 of 31, after the first fixes.**
  - **answer-by-name:** the name answered the question, but the self-test counted that
    question twice.
  - **plan-limit:** a request that named a connection was asked about anyway, a regression
    from the new rule for requests naming only a client.
  - **ambiguous:** the router asked in its reply, which the check didn't count as asking.
  - **client-default:** the task ended "not done", having taken "reply with the subject" as
    replying to the email.
- **30 of 31, after the second fixes.** client-default did the work, but the check missed
  that it used the mail connection, which it reached through the generic tool for connections
  added from other apps.
