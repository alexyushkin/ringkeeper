## Earlier the same day

This run is on main after beta.49, with three fixes made that day. Earlier runs, and what each
found:

- **37 of 38, on beta.49 as released.** **memory-reuse** failed: the first task answered who
  has spent the most and saved no note, so the next one had nothing to start from. Alone it
  passed 2 of 3 more times; the other time the first task again saved nothing. What tasks are
  told to save had examples for workflows and Airtable only, so it gained one for a database:
  which table holds what, and how they join. With it, the first task saved a note in 5 of 5
  runs, and the scenario passed 4 of 5. The fifth time the next question needed a column the
  note didn't name (the customer's city), so the task looked the tables up again.
- **36 of 38, with that change.** memory-reuse passed. Two others failed, and each found a bug:
  - **pushed-by-name:** the request named Acme's connection, and the router heard "Supabase".
    A request that names a service counted only the official remote server for it, so Demo
    shop's own Supabase connection didn't count, and the reply said Demo shop had "no Supabase
    connection". Nothing started, so nothing crossed, but the reason given was wrong, and any
    request that said "in Supabase" or "in Neon" would have been held the same way. A built-in
    connection now counts as the service it is.
  - **read-more:** the note under a cut-off result told the task to pass `next_offset` to
    read_more, which takes `offset`. The task did, was refused, and ended as failed. The note
    now says "offset set to next_offset".

  With both fixed, each passed 3 of 3 alone before this run.
